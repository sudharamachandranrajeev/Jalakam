# POC-1 results: media engine and streaming spine (Phase 4)

Status: **POC-1A subset done.** Every functional test passes. Most budgets are met.

Three marginal tail misses remain, all in §4:
- tick jitter p99, improved by a pacing fix but still above 1 ms in 4.4 % of 10 s windows;
- render-tick wall-time p99;
- GPU-stage p95, which is an upper bound.

The `sustained` checks added in this phase now flag the jitter miss, so it stays visible. No critical technology failed, so no architecture change is proposed. §6 lists evidence-backed amendments to existing ADRs.

Code, build steps and test commands: [`poc/README.md`](../../poc/README.md). Raw results (not committed, regenerated by `poc\scripts\run-tests.ps1`): `poc/out/results/<run>/<test>/summary.json`, plus engine logs, 1 Hz stats JSON lines, MediaMTX logs and pulled stream samples.

|---|---|---|

| `start-stop` | PASS | 3 cycles. Start to Active 1.5–1.6 s (first keyframe on the wire). Stream stop 205–209 ms. Record stop 212–221 ms. `OUT.ALREADY_ACTIVE` / `OUT.NOT_ACTIVE` returned. Every recording decodes. Restart with a timed run exits cleanly |
| `invalid-input` | PASS | `CAP.CAMERA.NOT_FOUND` and `CAP.AUDIO.NOT_FOUND` at start, and the engine keeps recording. A missing camera chosen at runtime is reported, then recovers. A malformed pipe request returns `CTRL.BAD_REQUEST` |
| `encoder-errors` | PASS | Unavailable encoder with no fallback: start refused with `ENC.OPEN_FAILED`, no output left behind. With fallback: `ENC.FALLBACK`, state `degraded`, the `h264_mf` stream decodes |

## 4. Performance against budgets (`performance-budgets.md`)

30-minute `sustained` run: 1860 s, 111 603 render ticks, stream + record + preview.

| Budget | Target | Measured | Verdict |
|---|---|---|---|
| Lagged + skipped frames | < 0.1 % | **0** lagged, 0 preview skipped | Met |
| Compositor + preview (GPU timestamps) | ≤ 1.0 + 0.4 ms | mean **0.68 ms**, worst 10 s p95 3.96 ms | Mean met |
| Colour conversion per encoder | ≤ 0.3 ms | **Not isolated** on this GPU (see below). A/B shows no measurable 3D cost | Not measurable; no evidence of a miss |
| Total engine GPU per frame | ≤ 4 ms p95 | PDH per-process 3D: **1.36 ms/frame** mean. Worst 10 s p95 of timestamped stages 3.96 ms (30 min run). 10 min re-run: 4.69 ms, with 17 of 609 windows above 4 ms | Mean met. p95 tail marginal (upper bound, see below) |
| Tick jitter | p99 ≤ 1 ms | Before fix (30 min): median 10 s p99 0.84 ms, **26 % of windows > 1 ms**, max 1.53 ms. After fix (10 min): median 0.52 ms, **4.4 % of windows > 1 ms**, max 1.09 ms | **Missed (marginal), improved** |
| Render thread per tick | ≤ 2 ms | Mean 0.81 ms wall. 10 s p99 median 1.71 ms, **26 % of windows > 2 ms**, max 10.9 ms | Mean met, tail open |
| Engine CPU | ≤ 1.5 cores | **0.28 cores** mean, 0.64 p95 (1.8 % of the machine) | Met |
| Engine RAM | ≤ 1.2 GB | Working set 158 → 131 MB | Met |
| Soak memory growth | ≤ 5 % | Private bytes 236 → 160 MB (**−32 %**) | Met |
| Engine VRAM | ≤ 1.0 GB | Dedicated GPU memory max **113 MB** | Met |
| Encoder input drops | 0 | **0** across 108 630 + 108 644 frames | Met |
| Audio | no glitches | 187 005 blocks, **8 underruns** over 30 min, drift 0.125 ms | Not a stated budget; reported |
| Preview | never back-pressures | 60.1 fps copied (min 57), 118 fps presented, 0 busy-slot skips, worst present gap p99 34.5 ms | Met |
| Shutdown | clean | **641 ms**, no engine threads alive (`SHUTDOWN.THREAD_LEAK` absent) | Met |

Output files from the soak:
- Recording: 1810.5 s, 2608.7 MB (11.5 Mbps average against the 12 Mbps target), 108 630 video packets. Decodes with no errors.
- Final stream pull: 10 s 1280×720. Decodes.

**Conversion cost not isolated.** `VideoProcessorBlt` (BGRA→NV12) does not show in D3D11 timestamp queries on the 3D queue. On the NVIDIA dGPU it also reads 0 on the PDH `VideoProcessing` and `Copy` engines (max 0.00 over 1871 samples). We ran an A/B test with the same scene for 45 s each:
- canvas only: 3D 1.57 ms/frame;
- canvas plus a 1080p NVENC record: 3D 1.54 ms/frame.

There is no measurable increase on any engine other than `VideoEncode`. The conversion is either negligible or accounted under `VideoEncode`, which has headroom (39 % average for two sessions). The `sustained` check now tests the whole-engine mean (3D + VideoProcessing ≤ 2.0 ms per frame) instead of a per-encoder figure. Before this change it passed on a 0 reading, which was a false pass.

**Jitter fix.** The high-resolution waitable timer alone overshot. The render loop now sleeps to 300 µs before the deadline and then spins (`yield_now`). The cost is at most about 2 % of one core. 10-minute re-run (`-Tests sustained -SustainMin 10`):
- windows over budget fell from 26 % to 4.4 %, still a strict miss;
- 1 lagged tick in 37 000, against 0 before;
- CPU 0.29 cores, unchanged.

Closing the gap needs measuring first. The next steps are MMCSS registration of the render thread (`AvSetMmThreadCharacteristics`) and a longer spin window. The other eight tests ran on the binary before this change. The change touches only the pacing loop.

**GPU p95 is an upper bound.** Stage timestamps measure elapsed GPU time between two points on our context. On a shared GPU (DWM composing at 120 Hz, the preview presenting at about 118 fps) they also include time slices given to other contexts. The PDH per-process mean (1.36–1.40 ms/frame) is the cost figure. The p95 tail needs GPUView/ETW to separate our work from preemption.

**Render tick tail.** Tick time is wall time, so it includes D3D11 calls that block on the driver. The 10.9 ms maximum is one window. It caused no lagged frames. The budget names thread CPU time. That needs `QueryThreadCycleTime` and is not measured yet.

**nvidia-smi.** The 30-minute run's nvidia-smi sampling failed (field name `temperatures.gpu`; the correct name is `temperature.gpu`). That is fixed. A 2-minute check run gave GPU utilisation 37 % (any engine), encoder 33 %, 1.06 GB VRAM for the whole GPU (all processes), 11 W, 42 °C. Every other GPU figure above comes from per-process PDH counters and D3D11 timestamps.

## 5. Limitations

- **Single canvas.** There was no portrait canvas, browser sources, desktop loopback, replay ring or third NVENC session. The load is lighter than the reference load, so budget results do not carry over to it.
- **Not the reference machine.** The RTX 4050 Laptop has an Optimus configuration. The display capture, compositor and encoders all run on the dGPU.
- **Device removal and permission denial were not exercised** (§3).
- **Reconnect policy differs from ADR-0014.**
  - The POC backoff caps at 30 s with no jitter. The ADR specifies 2 s → 15 min with jitter and at most 25 attempts.
  - `AUTH_REJECTED` keeps retrying instead of going straight to `Failed`. The local server has no auth to test it against.
  - The network test blocked for ~10 s, not 30 s.
- **Pre-roll packets count as drops.** Each output discards audio packets that arrive before its first video keyframe (4 per start). These are reported in the same `dropped_packets` counter as real drops. The product needs a separate `preroll_skipped` counter.
- **AAC uses FFmpeg's `aac` encoder**, not the MF AAC encoder named in the stack summary. Encode cost: 0.77 ms per 1024-sample frame on the CPU.
- **`h264_qsv` opens but was not tested in the pipeline.** `h264_amf` could not be tested (no AMD GPU).
- **Validation shares libraries with the engine.** `ffprobe`/`ffmpeg` decode checks use the same FFmpeg build. MediaMTX (independent Go RTMP implementation) accepting and republishing the stream is the independent check.
- **Silent microphone.** The Insta360 Link 2C mic is near silent on this machine (about −84 dBFS, also seen outside the engine). Metering was confirmed on the Intel array (−54 dBFS). A/V sync was not measured.
- **Leak trends are short.**
  - Camera switches show +0.38 MB/cycle. This is below the 0.5 MB threshold but not zero, and needs a longer run to show whether it plateaus.
  - Mic switching ran only 10 cycles. Memory is not checked for mic switching.
- **OS threads at exit.** About 49 unnamed threads (OS, Media Foundation, driver) and 2 foreign threads (one injected by a third-party shell-customisation tool) remain when shutdown finishes. None belong to the engine.

## 6. Architecture updates (evidence-backed)

None of these changes a decision. Each one tightens an existing ADR.

| ADR | Update | Evidence |
|---|---|---|
| ADR-0004 | The FFmpeg build is **LGPL-3.0-or-later** (`--enable-version3`), not LGPL-2.1. Compliance notes must name v3: allow relinking, and provide the source offer and install information | BtbN build configuration |
| ADR-0004 / ADR-0006 | The D3D11 hwframes pool for NVENC must use **separate textures** (`initial_pool_size = 0`), not an NV12 texture array. An NV12 array with `BIND_RENDER_TARGET` returns `E_INVALIDARG`. Render-target views are created as `TEXTURE2D` or `TEXTURE2DARRAY` to match `ArraySize` | Fails at startup on the test machine; works with the change |
| ADR-0007 | The MF camera must use the **asynchronous source reader** (or a flag-driven stop with a bounded wait). A cross-thread `IMFMediaSource::Shutdown` during a synchronous `ReadSample` hung on stop. The POC sets a flag and waits up to 1 s, calling `Shutdown` only as a last resort | Shutdown hang during development; after the fix, stops take about 210 ms and shutdown takes 0.6 s |
| ADR-0014 | An output becomes **Active on the first successful keyframe write**, not on connect. Between connect and that write it is `Starting` (or `Reconnecting`) with "connected; waiting for keyframe". A forced IDR is requested on every (re)connect | Before this, "Active" was reported before media flowed; start to Active is now 1.5–1.6 s |
| ADR-0015 | **Lock discipline**: never take two stats locks in one expression. A struct literal holding two guards deadlocked the render thread. Add a render-thread **watchdog** (`RENDER.STALLED` / `RENDER.RECOVERED`) and a shutdown check that names leftover engine threads (`SHUTDOWN.THREAD_LEAK`). Every engine thread must be named | Self-deadlock during development; the watchdog caught it |
| performance-budgets.md §1 | The per-encoder colour-conversion budget **cannot be measured with 3D-queue timestamps** and may not show on any PDH engine on NVIDIA. Measure per-stage timestamps (compose, preview) plus per-process PDH 3D/VideoProcessing/VideoEncode, and use an A/B run (outputs off vs. on) for the conversion share. GPU tick span from one timestamp pair is not a cost figure: it includes CPU submission gaps | §4 |
| performance-budgets.md §1 | Render pacing needs **timer + spin** to meet p99 ≤ 1 ms jitter. A high-resolution waitable timer alone is not enough | §4 |
| ADR-0008 | The 3-slot keyed-mutex shared-texture preview ring works **cross-process**: 0 ms acquire timeout, 0 busy skips over 30 min, the engine never blocks on the preview. Validated in a native Win32 window only; **POC-1C (Tauri child HWND) is still open** | §4 |

ADR status in `decisions/README.md` is unchanged. ADR-0002, 0004, 0006, 0007, 0008 and 0014 are partially validated by this POC. Full POC-1A validation still needs: a second canvas, replay, loopback, clapper A/V sync, TDR, a 30 s block and a 1 h soak on the reference machine.

## 7. Reproduce

```powershell
cd poc
. .\scripts\env.ps1
cargo build --release
.\scripts\run-tests.ps1 -LeakCycles 50 -SustainMin 30 -Run final   # ~50 min
.\scripts\run-tests.ps1 -Tests device-removal                       # interactive
```

Close GPU-heavy applications before the `sustained` test. Keep the machine on AC power with the default power plan.
